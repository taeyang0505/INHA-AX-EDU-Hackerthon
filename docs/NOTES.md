# LOOKteracy 참고 사항

이어서 작업할 때 알아 둘 점입니다. 2026년 11월 14일 `dist/` 코드 기준입니다.
파일 이름만 적은 것은 `dist/` 안의 파일입니다. 실행 방법은 `README.md`에 있습니다.

## 1. 현재 한계

실제 수업에 쓰기 전에 고치거나 운영 정책을 정해야 하는 부분입니다.

### 저장과 인증

- **기록은 이 브라우저의 localStorage에만 있습니다.** 서버 저장소와 데이터베이스가 없습니다. `scripts/serve.mjs`는 `dist/` 파일을 보내고 채점 API(`/api/grade`, `/api/grader`)만 처리합니다.
  - localStorage: `lookteracy-facepass-v1`(얼굴 등록), `lookteracy-gaze-sessions-v1`(시선), `lookteracy-submissions-v1`(답안·채점), `lookteracy-feedback-v1`(게시한 피드백), `lookteracy-attempts-v1`(응시 시도 기록), `lookteracy-goals-v1`(목표), `lookteracy-praise-v1`(칭찬), `lookteracy-cooperation-history-v1`(그룹 관리의 분류·편성)
  - sessionStorage: `lookteracy-demo-role`(역할), `lookteracy-demo-user`(로그인한 사용자), `lookteracy-cooperation-selected`
  - 학생 기록을 교사 화면에서 보려면 같은 컴퓨터의 같은 브라우저에서 같은 주소로 열어야 합니다. 브라우저는 `http://127.0.0.1:4186`과 `http://localhost:4186`을 서로 다른 곳으로 보고 기록을 따로 저장합니다. `#reset` 주소나 로그인 도움의 '모든 기록 초기화'는 localStorage에서 `lookteracy-`로 시작하는 값을 모두 지우고 sessionStorage도 비웁니다.
- **보관 개수가 정해져 있습니다.** 시선 기록은 브라우저 전체에서 최근 8개만 남습니다(`GZ.keepSessions`). 저장 공간이 모자라면 오래된 것부터 지웁니다. 제출 답안은 이름마다 마지막 1개, 응시 시도 기록은 이름마다 최근 10개, 지난 목표와 칭찬은 이름마다 최근 20개입니다.
- **사람을 이름으로 구분합니다.** 답안, 피드백, 응시 시도, 목표, 칭찬, 시선 기록을 모두 이름으로 찾습니다. 같은 이름과 같은 역할로 다시 등록하면 앞의 얼굴 등록을 덮어씁니다. 동명이인을 다루려면 사용자 ID로 바꿔야 합니다.
- **서버 쪽 인증과 권한 검사가 없습니다.** 역할은 sessionStorage의 `lookteracy-demo-role` 값뿐입니다. 화면 접근 검사(`look.js`의 `safePage()`)도 이 값만 봅니다. 개발자 도구에서 값을 `teacher`로 바꾸고 새로고침하면 교사 화면이 열립니다. 가입할 때 누구나 '교사'를 고를 수 있습니다.
- **얼굴 비교도 브라우저에서 합니다.** 등록 때 모은 128차원 특징값 6개를 localStorage에 저장하고, 로그인할 때 `facepass.js`가 이 값과 비교합니다. 눈 깜빡임 확인은 사진 한 장은 막지만 영상 재생까지 막지는 못합니다. 운영에서는 서버에서 비교하고, 서버가 돌려준 사용자 ID와 역할로 화면을 나눠야 합니다.
- **가입 단계 일부는 확인하지 않습니다.** 학급 연결 코드는 검사하지도 저장하지도 않습니다. 수집·보관 안내 체크박스를 누르지 않아도 다음 단계로 넘어갑니다.

### 실제 사용 전에 지울 개발용 진입 경로

- **페이스패스 로그인 화면의 작은 체크 아이콘**('학급 연결·페이스패스 등록' 오른쪽, `data-action="teacher-preview-access"`, `look.js`의 `login()`): `interactions.js`에서 `loginAs('teacher')`만 부릅니다. 얼굴 확인 없이 교사(김하늘 선생님) 공간으로 들어갑니다.
- **`#login-teacher`의 이메일·비밀번호 폼**: 로그인 버튼은 `action['login-teacher']`이고 `loginAs('teacher')`만 부릅니다. 입력값을 전혀 확인하지 않아 빈칸으로도 들어갑니다. 로그아웃 상태에서 `#t-dashboard` 같은 교사 주소를 열면 이 화면으로 옵니다.

### 시선 추적

- 웹캠 시선 추정(WebGazer 3.5.3, ridge 회귀)은 오차가 큽니다. 조명, 안경, 머리 움직임에 따라 더 커집니다. 보정이 끝나면 화면에 '평균 오차'(px, 실제로는 중앙값)가 나오니 그 값을 보고 판단하세요. 단어 하나 단위의 지표는 참고로만 보세요.
- 보정 정확도는 가운데 점 하나를 3초 동안 보고 계산합니다. 화면 가장자리 오차는 재지 않습니다.
- 정확도가 낮아도 다시 보정하라는 안내만 나오고 진행은 막지 않습니다. '점검 실패 안내 보기'에서 '카메라 없이 계속'을 고르면 시선 기록 없이 응시합니다.
- 분석할 때 시선 분포를 글자 영역에 맞춰 옮긴 위치도 함께 계산하고(`gzDriftCandidates()`), 단어에 배정되는 고정이 충분히 늘면 그 위치를 씁니다(`gzAnalyze()`, 기준은 2장). 보정이 한쪽으로 밀린 기록을 바로잡으려는 것이고, 학생이 지문 전체를 읽었다고 가정합니다.
- 읽는 중에 글자 크기나 창 크기를 바꾸면 그때까지의 시선 기록을 버리고 처음부터 다시 모읍니다.

### 샘플 데이터와 실제 기록이 섞이는 곳

- 학급 학생 10명(`look.js`의 `studentNames`, `baseStatus`)은 샘플입니다. 점수와 개념 상태는 `insight.js`의 `inExample()`이 이름마다 고정된 난수로 만든 값입니다.
- 지난 테스트 1회차(11월 6일, 서로 다른 근거를 비교하며 읽기)와 2회차(11월 11일, 정보의 신뢰성을 판단하는 기준)는 `cooperation.js`의 `coopTests`에 있는 샘플입니다. 회차별 결과 리포트(`insight.js`의 `rpPastView()`)도 샘플 값으로 그리고 '교사 검토 완료' 배지를 붙입니다. 이 리포트의 시선 고정 시간과 시폭은 샘플 독해 속도에서 식으로 만든 값입니다.
- 대시보드의 개념 진단·변화율·모둠 추천과 종합 결과의 상위 %는 실제 응시 학생과 샘플 학생을 함께 셉니다. 응시 현황, 학급·학생 표, 대시보드 위쪽 숫자는 샘플 10명만 셉니다.
- 실제 학생 이름이 샘플과 같으면(예: 김서윤) 이번 회차는 실제 기록으로 바뀌지만 1·2회차 샘플은 테스트 목록에 그대로 남습니다.
- 샘플 학생의 이번 회차 리포트는 모두 같은 고정 화면입니다. `teacher.js`의 `heatSnippet()`, `observations`, `reportAnswers()`의 예시 답안, 탭 위의 시선 지표(520 글자/분, 292ms, 7.9글자와 오래 머문 단어 등), 종합 결과('노력요함', '상위 73%')가 그대로 나옵니다. 오른쪽 아래 5개 영역 점수만 학생마다 다릅니다(`grading.js`의 `fbExampleScores()`, 2장). 그래서 종합 결과가 같은 화면의 CONCEPT · GROWTH 카드나 5개 영역 점수와 맞지 않을 수 있습니다.
- 그룹 관리의 4가지 수준 분류는 실제 분석이 아닙니다. `exampleClassification()`의 고정 명단을 3회차는 짧은 진행 표시 뒤에, 1·2회차는 처음부터 보여 줍니다. 대상도 샘플 학생뿐입니다. 대시보드 모둠 추천(`insight.js`의 `inGroups()`)과도 연결되어 있지 않습니다.
- 샘플 값이 화면마다 다릅니다. 학생 '나의 테스트'의 2회차와 홈의 '이전 테스트 피드백'은 '도시의 녹지는 누구를 위한 것인가'입니다. 홈 카드는 답안을 제출하거나 피드백이 게시되면 오늘의 지문 이름으로 바뀝니다. 학습 기록과 교사 화면의 2회차는 '정보의 신뢰성을 판단하는 기준'입니다. 3회차 날짜도 그룹 관리와 샘플 학생의 테스트 목록은 11월 13일, 학생 홈은 11월 14일입니다.

### 피드백과 성장 그래프

- **나의 강점·보완할 점·다음 읽기 전략은 모든 학생에게 같은 문구입니다.** `feedback.js`의 `studentFeedbackSections`(수정사항의 기본 문구)를 학생 화면과 교사 편집 화면의 초안에 씁니다. 교사가 그 학생에게 게시한 내용이 있을 때만 바뀝니다. 특정 낱말에서 시선이 오래 멈췄다는 문장처럼 실제 기록과 맞지 않는 내용이 있을 수 있습니다.
- 실제 채점과 시선 기록을 쓰는 곳은 학생 피드백의 '04 문항별 확인'과 오른쪽 레벨 카드, 학생 메뉴의 '나의 성장' 화면, 교사 리포트(응답·루브릭, 5개 영역 관찰, 5개 영역 점수, 종합 결과, 시선 지표, CONCEPT · GROWTH 카드)입니다. 답안만 있고 시선 기록이 없으면 탭 위의 시선 지표를 숨기고, 5개 영역 점수의 읽기 유창성은 50점으로 둡니다. 답안으로 만든 피드백 초안은 '개인 피드백 편집'에서 '분석 초안 불러오기'를 눌러야 나옵니다.
- 학습 성장 그래프(8~12월, 레벨 2·3·2·4·4)는 `feedback.js`의 `growthExample` 고정 값입니다. 학생 피드백 화면의 '나의 성장' 카드와 교사 리포트의 '학습 성장 추이'가 이 값을 씁니다. 12월은 아직 지나지 않은 달입니다. 실제 회차별 점수 그래프는 '나의 성장' 화면(`insight.js`의 `inChart()`)에 있습니다.
- 리포트 이미지(PNG, `interactions.js`의 `exportReport()`)는 학생 이름만 바뀌고 내용은 고정입니다. 샘플 지문 구간, 520·292ms·7.9 수치, 기본 5개 영역 문장을 그립니다.

### 그 밖의 기능

- **OCR은 필기를 읽지 않습니다.** 필기 모드에서 'OCR로 변환'(`action['ocr-example']`)을 누르면 문항마다 정해진 문장을 넣습니다. 확인란을 체크하고 적용하면 그 문장(고쳤다면 고친 문장)이 그 문항의 답안이 되고, 제출하면 채점됩니다. 필기 획은 저장하지 않습니다. 실제 OCR을 붙이거나 버튼을 막아야 합니다.
- **보호자 소식 창을 열 방법이 없습니다.** `insight.js`에 `action['in-parent']`(문안 만들기)가 남아 있지만 이 동작을 부르는 버튼이 없습니다. 복사 버튼(`action['in-parent-copy']`)은 그 문안 창 안에만 있습니다. 문안의 '3회차'도 고정입니다. 다시 쓸지 정한 뒤 코드를 지우거나 버튼을 연결하세요.
- **테스트 배정은 메모리에만 남습니다.** 수업·테스트 구성에서 지문을 고쳐 배정하면 `st.assignment`에만 들어갑니다. 같은 탭에서만 학생 화면에 반영되고 새로고침하면 사라집니다. 문항, 루브릭, 채점은 원래 지문 기준 그대로입니다.
- **Claude 채점은 선택 기능입니다.** `npm install`과 `ANTHROPIC_API_KEY`(`.env` 또는 환경 변수)가 있어야 합니다. 없으면 `/api/grade`가 503으로 답하고 앱은 `grading.js`의 규칙 기반 채점을 그대로 씁니다. 켜 두면 제출할 때마다, 그리고 교사가 리포트에서 'Claude로 다시 채점'을 누를 때마다 지문, 문항, 루브릭, 답안, 시선 요약, 응답 시간을 Anthropic API로 보냅니다. 학생 이름은 보내지 않습니다. 실제 학생 답안을 보내기 전에 학교 정책을 확인하세요. 모델은 `LOOKTERACY_GRADER_MODEL`로 바꾸고, 기본값은 `claude-opus-5-5`입니다.
- `styles.css`가 Google Fonts를 불러옵니다. 인터넷이 없으면 기본 글꼴로 보입니다.
